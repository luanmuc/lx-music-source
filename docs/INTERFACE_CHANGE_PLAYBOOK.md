# 接口变更应对手册（实战速查）

> 音源挂掉 90% 是平台改接口。本手册把六类高频变更模式查表化，同时服务两个场景：
> - **修源取证**：源挂了查原因、定位变更类型、套解法
> - **候选实证取证**：新候选判活判否（与 huanyin 判否同款动作）
>
> **活文档原则**：骨架先立完整，真实案例随实战回填——修一次、回填一行，不是一次写死的百科。

---

## 一、六类变更模式速查表

| 模式 | 典型症状 | 快速定位 | 解法方向 |
|---|---|---|---|
| **签名/鉴权类** | 401 / 403 / 返回空 / 明明参数对却拿不到 | 请求头少了 sign / token / eapi；控制台看原请求对比新旧 | 补签名参数 / 换鉴权方式 / 等上游修复 |
| **字段改名类** | 能搜到歌、列表正常，但取不到播放链 | 搜索接口返回的 songmid → 取链接口要 rid / id / hash，字段名对不上 | 取链前加字段映射（songmid→rid） |
| **域名/防盗链类** | 连接失败 / NXDOMAIN / 403 | `dig +short <domain>` 解析失败 = 域名失效；CDN 校验 Referer/UA | 换备用域名 / 加 Referer 头 / 绕 CDN 直链 |
| **响应格式类** | 解析失败 / JSON .parse 报错 / 单引号包裹 | curl 抓原始响应，看首字节是 `{` 还是单引号；content-type 是 JSON 还是 text | 换解析器 / 去单引号再 parse / 转义 |
| **音质档位变化类** | 降级链异常 / flac 停供 / 320k 改名 | 取链返回的音质名和我们期望的对不上（flac → flac24bit / high → 320k） | 补音质映射表 / 调整降级顺序 |
| **风控限流类** | 间歇失败 / 业务 502 / 错误信息提示 IP 被限 | 同一源有时通有时不通；错误码是业务码不是网络码 | 加延迟 / 换 IP / 触发式待办（上游恢复再评） |

## 二、共用取证工具表

| 动作 | 命令 / 方法 | 看什么 |
|---|---|---|
| **域名是否可解析** | `dig +short <domain>` / `nslookup <domain>` | NXDOMAIN = 域名失效型；有 IP 返回 = 域名活着 |
| **原始响应体** | `curl -s -i <url>` | 看业务码（code/msg）、字段结构、首字节格式，不看摘要 |
| **响应头/格式** | 看 curl 返回的 content-type / 首字节 | 判断 XML / JSON / 纯文本 / 单引号 JSON |
| **git log 对比** | `git log -p --follow lx-source.js` 搜该源关键词 | "刚改过才挂"（我们引入的问题）vs "长期未动突挂"（上游改了） |
| **HTTP 状态码** | 看 curl 返回的状态行 | 200 = 通；403 = 鉴权/防盗链；404 = 路径变了；502 = 上游挂了；429 = 限流 |
