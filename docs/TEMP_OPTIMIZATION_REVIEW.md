# 临时优化审查清单（v8.9.1 之后）

> 用途：供另一个豆包账号审查，确认哪些值得做、哪些设计合理不动。
> 状态：临时文档，审查完即删。
> 整理时间：2026-11-06

---

## 🔴 高优先级（直接影响用户体验）

### 1. 跨档 12s 总预算太激进
- **现状**：`raceBudgetMs = 12000`（12s）跨音质档共享（flac → 320k → 128k）
- **问题**：flac 档如果 9~10s 才失败，降档到 320k 只剩 2~3s，根本不够竞速
- **影响**：高音质失败后低音质交付时延变长，用户等更久才听到歌
- **建议**：按档分配预算（flac 8s / 320k 6s / 128k 5s），或总预算提到 18s

### 2. 档位短路 6h 探路窗口太长
- **现状**：`qualityShortCircuitProbeMs = 21600000`（6h）
- **问题**：源临时故障 10min 就恢复了，用户 6h 内都拿不到该档高音质
- **影响**：源临时波动期间，用户被"永久降级"6 小时
- **建议**：缩短到 1h（3600000），或按源健康分自适应

### 3. successCache 6h TTL 对高音质太长
- **现状**：`cacheTtlMs = 21600000`（6h）所有音质统一
- **问题**：flac/320k 链接有效期短（几小时），缓存 6h 可能拿到已失效的旧链
- **影响**：缓存命中但链接已死，反而拖慢竞速（先试缓存→410→再换源）
- **建议**：高音质（flac/320k）缓存 TTL 缩到 30min，128k 保持 6h

## 🟡 中优先级（运维/稳定性）

### 4. 冷启动源探测超时不匹配
- **现状**：`healthCheckIntervalMs = 600000`（10min），探测超时默认 8s
- **问题**：huibq onrender 冷态 30s，探测超时 8s 直接判死，实际源是好的
- **影响**：免费冷启动源被误判死源，健康面板显示假死
- **建议**：`coldStart: true` 的源探测超时放宽到 60s

### 5. probe-history.jsonl 无大小限制
- **现状**：probe.js 追加写，30 天以前的记录不清理
- **问题**：每天追加一次，一年 365 条，虽然不多但也没自动清理
- **影响**：仓库体积缓慢增长，health-daily 读取时文件越来越大
- **建议**：自动清理 30 天以前的记录

### 6. half-open 恢复太激进
- **现状**：half-open 试探成功 → 直接 closed（全开）
- **问题**：如果源只是临时恢复（CDN 缓存命中），全开后很快又挂，反复震荡
- **影响**：源在熔断/恢复之间反复横跳，健康分波动大
- **建议**：half-open 成功后先降级到 `batch: 2`（后批），连续 3 次成功再升回前批

## 🟢 低优先级（锦上添花）

### 7. 历史快照 60 条≈10 小时，趋势图太短
- **现状**：healthHistoryMax = 60（10min/条）
- **问题**：趋势图只能看当天 10 小时，跨天就断了
- **建议**：扩到 144 条（24 小时）或 432 条（3 天）

### 8. UA 池只有 4 套
- **现状**：4 套移动 UA 轮换
- **问题**：长期运行如果上游 UA 风控升级，4 套可能不够
- **建议**：扩到 8~10 套

### 9. gdWy batch:2 降后批的时延代价
- **现状**：wy flac 首批只有 suyin163 + juheWy，gdWy 在第二批（等 300ms 错峰）
- **问题**：wy flac 首次交付时延增加
- **结论**：配额源（5min/50次）降后批是为了省配额，设计合理，**建议不动**

### 10. 版本串三处手动同步
- **现状**：@description / @version / logInfo 三处手动同步
- **问题**：v8.9 就因为漏了 logInfo 导致 self-check 报错
- **结论**：self-check 脚本已存在，只是 v8.9 那次没跑，**建议不动**

## 汇总

| 优先级 | 数量 | 建议 |
|---|---|---|
| 🔴 高 | 3 | 值得做，直接影响用户体验 |
| 🟡 中 | 3 | 值得做，提升稳定性 |
| 🟢 低 | 4 | 2 个可做、2 个建议不动 |

4. 第 4 条（冷启动探测）：onrender 冷态 30s 是实测值吗？探测超时放宽到 60s 合理吗？
